# Action Engine

The Action Engine converts reasoning into reality-contact.

## 1. Action gate

Move into execution when:

- the next step is reversible and bounded;
- further analysis cannot materially change the next step;
- a real test has higher information value than more discussion;
- the user explicitly requests execution and no severe risk requires escalation.

## 2. Priority

Rank work qualitatively by:

`Impact × Confidence ÷ Effort`

Use this to identify the first action, not to create fake precision.

## 3. Bottleneck first

Before optimizing a system, identify the current constraint.

Ask:

> If only one thing improved this week, which change would increase total system output the most?

Avoid improving non-bottlenecks merely because they are easy.

## 4. Minimum Validation Action

The MVA is not simply the smallest task.

It is:

> the lowest-cost real action that reduces the most decision-relevant uncertainty.

Define:

- **uncertainty** — what must we learn?
- **test** — what will we actually do?
- **signal** — what observable result matters?
- **threshold** — what result changes the decision?
- **sample/time** — how much evidence is enough?
- **branch** — continue / modify / stop.

## 5. Feedback architecture

Every meaningful experiment should define:

- metric/signal;
- baseline;
- observation window;
- success threshold;
- failure threshold;
- confounders;
- decision after observation.

Do not use vanity metrics when decision metrics are available.

## 6. OODA

For dynamic execution:

1. **Observe** — current reality and new evidence.
2. **Orient** — what changed relative to assumptions?
3. **Decide** — one bounded next move.
4. **Act** — execute.
5. Repeat with updated beliefs.

## 7. Kill criteria

For projects that can absorb unlimited resources, predefine stop conditions.

Good kill criteria are:

- observable;
- time-bounded;
- tied to economics/strategy;
- hard to rationalize away after failure.

Examples:

- three validated cohorts remain below unit-economics threshold;
- critical dependency cannot meet required SLA by date;
- retention stays below threshold after two targeted revisions.

## 8. Scale criteria

Also define when to double down:

- repeatable signal;
- economics work at current scale;
- bottleneck understood;
- downside capped;
- operational capacity exists.

## 9. Action output

End with:

- **Now:** next concrete action.
- **Measure:** what to observe.
- **Decision rule:** what happens after the result.

When analysis should end, say: **停止分析，进入行动。**
